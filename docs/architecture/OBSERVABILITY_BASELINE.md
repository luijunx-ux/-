# 可观测性基线

## 目标

Alpha 阶段用最少但可验证的信号回答三个问题：服务是否存活、依赖是否就绪、一次请求在哪里失败。

## 健康检查

- `GET /health`：兼容已有部署探针。
- `GET /health/live`：仅判断 API 进程是否能响应，不访问外部依赖。
- `GET /health/ready`：检查 PostgreSQL；配置 Redis 时同时检查 Redis。全部必需依赖可用返回 `200`，否则返回 `503`。
- 健康检查只返回依赖名称和状态，不返回主机、端口、凭据或驱动异常。

## 请求追踪与访问日志

- 客户端可通过 `X-Request-ID` 传入 1–64 位字母、数字、点、下划线或连字符。
- 无效或缺失的标识由服务端生成，并通过响应头 `X-Request-ID` 返回。
- 每次请求输出一条 JSON 日志，包含时间、级别、请求标识、方法、路径、状态码和耗时。
- 路径不包含查询参数；日志不记录请求体、Authorization、Cookie、出生信息、经纬度或模型密钥。

## Alpha 运维建议

- 将 `5xx` 比例、`/health/ready` 连续失败和请求耗时 P95 作为第一批告警信号。
- 日志采集系统以 `request_id` 串联 API、Agent 与外部服务事件。
- 生产环境保持结构化日志，并在采集侧设置访问控制和保留期限。
