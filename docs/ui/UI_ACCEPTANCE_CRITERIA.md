# UI 视觉审核与提交门禁

## 硬性验收

- [ ] Forest 明显呈现自然、柔和、森林/植被与呼吸感。
- [ ] Obsidian 明显呈现黑曜、星空、蓝紫与暖琥珀生命光。
- [ ] 两主题共享信息架构，但不是简单明暗色反转。
- [ ] 首页五运六气与星辰节律为同等级双核心入口。
- [ ] 首页不进入二级页即可看到今日摘要和四类生活建议。
- [ ] AI 生命球有独立视觉身份，不是普通机器人/聊天图标。
- [ ] 不呈现工业 Dashboard、交易终端、医疗仪表或游戏 HUD 风格。
- [ ] 不使用未经批准的伪精确生命分数。
- [ ] 加载、空、错误、离线和数据过期状态不破坏主题。
- [ ] 中文无截断/溢出；系统字体放大后核心操作仍可用。
- [ ] 对比合理；触控目标至少 44×44；信息不只靠颜色表达。
- [ ] 减少动态模式可用，动画不会阻断操作。

## 审核材料

每次请求视觉审核必须提供真实运行截图，不接受只看代码：

1. Forest：首页、五运六气、星辰节律、AI 助手。
2. Obsidian：首页、五运六气、星辰节律、AI 助手。
3. 至少一个 Android 模拟器尺寸；Web 另附桌面或窄屏截图。
4. 一组大字体或窄屏截图，以及加载/空/错误状态中的至少一种。
5. 附本清单自检结论、测试结果和已知视觉差异。

## Git 硬门禁

- 用户明确回复“视觉审核通过”之前，不得 `git add`、`git commit` 或 `git push`。
- “审核通过”若未明确指出视觉，必须视为尚未通过视觉审核。
- 自动测试、构建成功、功能审核或接口审核均不能替代视觉审核。
- 审核未通过时保留工作区修改并继续迭代，不提交临时版本。
