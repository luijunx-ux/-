## 1. 主题定位

Vitality Life 是 Forest Life 与 Obsidian Life 之外的第三种主题方向。它借鉴现代健康应用的数据层级、留白和可扫描卡片结构，同时以高饱和、真实、亲切的日常生活摄影增强生活气息。

关键词：`悦活`、`日常`、`阳光`、`亲切`、`清爽`、`真实摄影`、`数据易读`、`行动导向`。

本主题不得直接命名为 Fitbit 风格，不复制第三方品牌、图标、组件或版式；只借鉴通用健康应用的信息设计原则。

## 2. 与现有主题的关系

- Forest Life：自然沉浸、荷叶露珠、森林与呼吸感，继续作为默认主题。
- Obsidian Life：黑曜深空、蓝紫与琥珀生命光，继续作为深色主题。
- Vitality Life：浅色健康界面、生活摄影和清晰数据卡，作为第三主题候选。
- 三个主题共享信息架构、数据模型、业务含义和无障碍要求，不得产生不同的计算结论。
- 当前冻结需求仍以 Forest/Obsidian 双主题为 P0；Vitality 的正式开发排期须另行进入 P1 或经需求基线明确变更。

## 3. 首页信息架构

顺序建议固定为：

1. 日期、节气、地点与问候。
2. 当日生活主图。
3. 今日生命状态与核心数据窗口。
4. AI Agent 综合分析。
5. 五运六气摘要、生活配图与健康建议。
6. 星辰节律摘要、生活配图与健康建议。
7. 用户重点状态。
8. 今日、节律、记录、我的底部导航。

五运六气与星辰节律必须保持同等级入口；点击后分别进入“专业术语 / 通俗解释”双列详情页。

## 4. 今日生命状态窗口

首版预留四项核心内容：

| 指标 | 展示规则 |
|---|---|
| 生命参考状态 | 按冻结的生命参考分 V0.1 显示状态；满足覆盖率与个人基线门槛时可同时显示数值 |
| 今日步数 | 来自系统健康平台或穿戴设备；无授权时显示连接或暂无数据 |
| 睡眠时长 | 显示数据来源和记录日期；不得将单次时长直接解释为疾病风险 |
| Readiness / 恢复准备度 | 仅在有经验证算法及所需数据时计算；否则显示暂不可用 |

所有示例数字只用于视觉排版，不是算法事实。正式数值必须遵循 [`生命参考分算法规范 V0.1`](../product/LIFE_REFERENCE_SCORE_V0_1.md)，由可测试规则引擎计算；LLM 只能解释，不得自行打分。

## 4A. 首页板块一：顶部问候与每日生活主图（内容冻结）

冻结日期：2026-09-03

概念样板内容顺序：

1. 系统状态栏。
2. 日期与星期。
3. 当前节气及通俗阶段描述。
4. 个性化问候。
5. 一句非诊断、非宿命的温和陪伴文案。
6. 每日生活主图。
7. 地点、天气、温度、空气质量标签。
8. 图片生活主题、行动标题和节气生活提示。
9. 图片更新状态与环境数据更新时间。
10. 下一个“今日生命状态”板块自然露出。

### 数据字段与后续接口映射

| UI 字段 | 建议字段 | 数据来源/端口 | 缺失或失败状态 |
|---|---|---|---|
| 用户称呼 | `display_name` | 当前用户/默认生命档案；现有 `/api/v1/profiles/{profile_id}` 可提供档案名称，后续区分昵称字段 | 显示“你好” |
| 日期与星期 | `local_date`, `weekday` | 客户端时钟 + 用户时区；服务端校验 | 使用设备时区并标记 |
| 节气 | `solar_term`, `solar_term_phase` | 后续确定性节气服务，不得由 LLM 猜测 | 显示“节气数据暂不可用” |
| 地点 | `location_name` | 用户授权的当前地点；未授权时可使用生命档案地点但须明确含义 | 显示“未选择地点” |
| 天气与温度 | `condition`, `temperature`, `weather_observed_at` | P1 环境数据适配器/聚合接口 | 显示“天气暂不可用” |
| 空气质量 | `aqi`, `aqi_level`, `aqi_observed_at` | P1 AQI 数据适配器/聚合接口 | 显示“空气数据暂不可用” |
| 每日图片组 | `image_set_id`, `hero_asset`, `alt_text` | 预审内容库；后续每日内容接口 | 使用内置默认图 |
| 图片生活主题 | `life_theme` | 预审内容配置，与图片组绑定 | 隐藏主题标签 |
| 行动标题 | `hero_action_title` | 经审核的生活建议模板；可由规则选择，LLM 不得任意生成事实 | 使用通用温和文案 |
| 节气提示 | `seasonal_note` | 确定性节气结果 + 经审核解释模板 | 隐藏节气提示 |
| 更新时间 | `image_updated_at`, `environment_updated_at` | 各自数据源元信息 | 明确显示过期/离线 |

建议后续新增只读聚合端口 `GET /api/v1/home/header`，统一返回顶部展示模型；它只聚合已授权的数据，不承担节气计算、天气生成或 AI 推断。正式实现前需先完成 API schema、隐私和缓存设计评审。

### 展示规则

- 问候按本地时间选择早上好、下午好或晚上好，用户名称缺失时不出现多余标点。
- 节气必须由确定性算法产生；“秋意渐起”等为审核过的通俗解释模板。
- 当前地点与出生地点必须区分，禁止把出生地点当成实时所在地而不提示。
- 天气和 AQI 必须显示观测时间；超过新鲜度阈值时显示“数据已过期”。
- 每日图片同一自然日保持稳定，跨日更换；不得随每次刷新随机变化。
- 主图文案不得声称天气、星象或五运六气导致疾病、情绪或具体事件。
- 图片加载失败时保留文字、地点与环境信息，并使用主题默认背景。
- 图片替代文本描述生活场景，不使用“健康、年轻、完美”等主观判断。

## 5. 生活摄影系统

主页每天可切换一组照片，每组建议三张：

- 顶部主图：晨间活动、通勤、散步、自然与社区生活。
- 五运六气配图：饮食、饮水、环境、四季起居与日常活动。
- 星辰节律配图：专注、沟通、家庭、情绪记录和夜间恢复。

同一天保持图片组稳定；不得每次刷新随机变化。推荐建立预审图片库，由日期、季节、真实天气和建议主题选择图片，不在用户打开首页时实时生成。

首组图片：

- [`vitality-life-breakfast-v1.jpg`](previews/vitality/vitality-life-breakfast-v1.jpg)
- [`vitality-life-evening-v1.jpg`](previews/vitality/vitality-life-evening-v1.jpg)

摄影要求：

- 色彩明快、自然光、真实生活感，避免生硬摆拍。
- 人物年龄、性别、身体状态、家庭结构和生活场景保持多样性。
- 不使用医疗、药物、恐惧、极限运动或不现实身材画面。
- 图片只能支持情绪与场景表达，不得作为健康计算输入或医学证据。
- 提供无人物自然模式、减少图片模式和低流量降级。
- 所有图片必须有无障碍描述、授权记录和内容审核状态。

## 7. 布局与组件

- 移动端基准 Frame：`390 × 844`，同时验证 `360 × 800` 和大字体。
- 页面水平边距：16–20；区块间距：12–20。
- 主卡圆角：18–22；图片圆角：14–20。
- 生活主图高度约 112–140；模块配图约 88–104。
- 正文建议不低于 16sp；触控目标不小于 `44 × 44`。
- 数据数字可以突出，但必须附单位、来源、时间或状态说明。
- 组件继续复用 `LifeStatusCard`、`YunQiCard`、`ZodiacCard`、`AdviceCard`；摄影区域作为可选主题插槽，不改变组件数据契约。

## 9. 状态与降级

- 图片加载失败：保留卡片高度，使用主题色和图标占位，不影响文字建议。
- 离线：使用最近缓存的已审核图片组或内置默认组。
- 低流量：只加载顶部主图，模块配图改为色块或插画占位。
- 减少图片：隐藏人物照片，使用自然景物或低饱和背景。
- 数据缺失：指标显示“暂无数据/连接设备”，不得生成示例数字。

## 10. 视觉验收

- 一眼能感到真实、明快、亲切的生活气息，而不是纯白办公 Dashboard。
- 摄影增强认同感但不压过生命状态、健康建议和数据来源。
- 五运六气与星辰节律保持同等级入口和接近的信息量。
- 四项核心指标在窄屏和大字体下无截断。
- 覆盖加载、图片失败、离线、无设备、数据不足和减少图片模式。
- 必须提供 Forest、Obsidian、Vitality 的真实运行截图；用户明确回复“视觉审核通过”后才允许 Git 提交。
