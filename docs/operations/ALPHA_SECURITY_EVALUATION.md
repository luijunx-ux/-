# Alpha 安全评测基线

## 评测范围

Alpha 放行前同时检查代码供应链、账户与数据隔离、AI 输出边界、运行配置、日志隐私和恢复能力。
自动测试不能替代安全与隐私负责人的人工审核。

## 自动门禁

- Gitleaks 扫描完整 Git 历史，阻止密钥、令牌和私钥进入仓库。
- `pip-audit` 检查 Python 运行及开发依赖；存在已知漏洞时 CI 失败。
- 每次 CI 生成 CycloneDX JSON 格式后端 SBOM，保留 14 天用于版本追溯。
- Trivy 在一次性 GitHub Runner 中扫描后端镜像的系统与 Python 库；存在已有修复方案的高危或
  严重漏洞时阻断。扫描 Action 固定到官方发布提交，不在本机向第三方容器暴露 Docker 控制接口。
- 后端测试覆盖密码哈希、JWT 受众、Refresh Token 轮换、一次性令牌、限流失败关闭、
  用户数据隔离和账户删除级联。
- AI 安全评测集验证诊断、治疗、用药、宿命或绝对预测等表达被阻止并走确定性降级。
- 容器门禁验证非 root 运行、生产配置快速失败、迁移、就绪探针及隔离恢复。

## 阻断规则

- 真实密钥或用户数据进入 Git、镜像、日志或构建产物：立即阻断。
- 运行依赖存在无已批准例外的已知漏洞：阻断。
- 高危漏洞仅允许在安全与隐私负责人记录影响范围、临时缓解、负责人和到期日后例外；
  不允许永久忽略或使用宽泛漏洞白名单。
- 鉴权绕过、跨用户数据访问、删除失效、生产模板密钥或 Redis 限流失败开放：阻断。
- AI 输出包含医疗诊断/治疗、恐吓、宿命断言或将 LLM 当作确定性计算结果：阻断。

## 人工审核

- 核对隐私同意、数据用途、删除入口、日志保留和第三方数据处理条款。
- 核对 SMTP、模型供应商、备份存储和监控平台的最小权限及密钥轮换。
- 核对最新 SBOM、依赖审计结果和容器基础镜像更新日期。
- 使用 Alpha 发布清单记录发布、安全/隐私、恢复、产品/内容四类负责人签字。
